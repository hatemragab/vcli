## Ranked finding

### F1 — P2: generated installation shortcut leaves the advertised operational workflow blocked

**Location:** `src/recipes/render-checks.ts:63`–`66`; related generated guidance at `src/recipes/selected-guidance.ts:25`. The enforcing consumer is `src/commands/operational-commands.ts:134`–`140`, `:370` and `:461`; inspection retains the recorded install outcome at `src/engine/inspection.ts:222` and only downgrades unhealthy installations at `:272`–`284`.

**Trigger:** initialize with `--skip-install`, then run the generated `make install` followed by `make dev`. The install target runs only `npm install --install-links`. Even when npm succeeds and the installed manifests are healthy, that command does not record `outcomes.install = 'completed'` in `vcli.lock.json`. `make dev` delegates to `vcli dev`, which refuses the still-pending outcome with `OPERATION_DEPENDENCIES_PENDING`. The same mismatch affects release wrappers after source-only changes that invalidate installation. Direct npm build/start remains available, but it does not repair the generated Makefile workflow.

**Smallest useful correction:** make the generated install workflow finish through the pinned `vcli install` lifecycle, bootstrapping its local executable when absent, and explain that sequence in generated guidance. Retain the existing named local-package re-resolution and post-install validation rather than accepting plain npm success as VCLI installation evidence. Add one focused source-only-init → generated-install-target → operational-preflight regression when the coordinator implements the correction; this review executed none of those commands.

**Evidence/status:** established by the current command/state source trace, not runtime reproduction. Routed to the coordinator as `msg_38c52d5712a3`. This review does not modify implementation or classify the active maintenance gate's failure as the same defect.
