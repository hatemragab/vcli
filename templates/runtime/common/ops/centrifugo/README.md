# Selected Centrifugo service

The generated service descriptor records the topology. Centrifugo is pinned to v6.10.3. Single-instance selects its memory engine and one API process. Cluster selects its Redis engine, shared private Redis>=6.2 and the shared selected native application database. Cluster requires CENTRIFUGO_ENGINE_REDIS_ADDRESS in the private service environment; it never starts or provisions Redis. Authentication/TLS for Redis is an operator responsibility. There is no app Redis SDK, history, replay, presence, client publication or client subscription.

Public client port8000 and internal API/health port9000 bind to loopback in this development Compose asset. Expose only /connection/websocket at ingress. Keep the server API, internal listener and backend /api/realtime/centrifugo/connect and /refresh callbacks private. Container deployments replace host-gateway callbacks with the private API hostname. API callbacks need no affinity because grants and exact client/generation leases share the native database. Cluster service nodes share one Redis engine address/prefix; API publication can use any healthy Centrifugo node.

Prepare an untracked private service environment file. CENTRIFUGO_API_KEY equals the app's independent API key. CENTRIFUGO_CALLBACK_HEADERS is JSON with X-Centrifugo-Proxy-Secret equal to the app's distinct CENTRIFUGO_PROXY_SECRET. Both secrets contain at least32 characters. ALLOWED_ORIGINS matches the app. The service's http_headers/emulated_headers are empty, so client Authorization/provider tokens and client-supplied callback headers never reach the backend. No direct JWT key or anonymous bypass is configured.

Run the explicit schema command before startup. The owner initializeRealtime contribution creates native grant/rate/binding/node state and realtime-v1; ordinary bootstrap only checks readiness. One-use grants last at most30 seconds and contain no API credential. Server subscriptions and disconnect user addresses are scoped to exact session, installation generation and provider client.

For local native API port3100, the asset uses Docker's host gateway. App CENTRIFUGO_API_URL is http://127.0.0.1:9000/api, client URL is ws://127.0.0.1:8000/connection/websocket and private health is http://127.0.0.1:9000/health. The selected client imports centrifuge5.8.0, obtains a fresh grant on reconnect, recovers REST state and removes handlers/connection on close.

An explicitly authorized run uses docker compose --env-file /path/to/private-services.env -f ops/centrifugo/compose.yml up -d. Review image downloads/resources under host rules first. Limits are192MiB/0.5CPU; enclosing deployment supplies approved network/cgroup parent. Rendering never starts services or changes host limits.

Connect denial returns HTTP200 disconnect4501; temporary failure uses error100. For this pinned version, refresh retry uses HTTP503 because RefreshResponse ignores JSON error/disconnect fields. Refresh denial uses HTTP200 result.expired:true. Shared references lease10 seconds and refreshed grants expire in at most5 seconds. Backend sweeps run each second with2-second authority deadlines; all private sends recheck authority. Each failed refresh HTTP request grants this pinned provider another60 seconds before retry, and repeated failures can prolong a silent connection; the backend's shared lease and current-authority checks still deny private disclosure. There is no hard close deadline during total API/service/network outage, and already dispatched bytes cannot be recalled.

API restart can refresh native bindings. API drain stops admission/publication and aborts HTTP requests; valid cluster clients may continue through another API node. Provider restart disposes its sockets and the SDK obtains new grants. Timeout/transport/malformed/temporary API failure reports unknown acceptance, never safe automatic resend.

Rendering, health and controlled wire peers are separate from actual service/Redis/native two-node acceptance. Validate exact service version, callback denial/retry, engine/adapter outage, generation revocation, restart and private ingress before a deployed cluster support claim.
