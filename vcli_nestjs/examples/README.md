# Reference and generated example projects

These are hand-built NestJS examples for owner review before VCLI implementation. They are independent applications, not runtime database profiles inside one project. VCLI is now implemented separately; the packed generated-stack evidence is in [CLI verification](../docs/CLI-VERIFICATION.md). These references retain their distinct provenance.

| Project                                                    | Database fixed in source       | Current evidence                                                  |
| ---------------------------------------------------------- | ------------------------------ | ----------------------------------------------------------------- |
| [reference-api](reference-api/README.md)                   | MongoDB / Mongoose only        | Build/static, native DB, HTTP/protocol and browser/restart passed |
| [reference-api-postgres](reference-api-postgres/README.md) | PostgreSQL / Drizzle + pg only | Build/static, native DB, HTTP/protocol and browser/restart passed |

The database is selected once when initializing a future generated project. Only its chosen database implementation, schema, dependencies, configuration and service artifacts belong in that output. There is no runtime adapter selector, alternative database dependency or application memory recipe. Test doubles remain test-owned.

Both examples use flat feature entity/service/module/controller files, directly injectable services, one class per file and enforced acyclic file/type/feature dependencies. Their BaseRepository classes expose useful native create/read/query/pagination/update/upsert/delete/batch/iteration helpers. Mongo additionally uses native population/aggregation/bulk; SQL uses native joins/grouping/conflict targets. Existing HTTP/auth/session/storage/push/realtime behavior must remain verified.

See [the implementation contract](NATIVE-DATABASE-CONTRACT.md) and [coordinator prompts](agent-prompts/) for the current task. Each app's verification record identifies actual commands, source fingerprint and evidence levels. MongoDB passed 146 tests and PostgreSQL 147, with one optional Vector/Logdy skip each and three HTTP/protocol journeys each. The separately completed native logging evidence is preserved. Previous combined-catalog acceptance remains historical. External Firebase/cloud/device/deployment and unfinished advanced modes remain explicitly pending.

## CLI-generated username notes example

[test_notes_mongo](test_notes_mongo/README.md) was generated by the installed private CLI after entering its name at the first interactive `Project name` prompt. The underscore name is preserved. Its [configuration](test_notes_mongo/vcli.json) selects MongoDB, local username/password JWT authentication, local server storage/private media, owned notes and retained application/database/infrastructure logs. Mail and realtime providers are absent.

The offline installation, generated architecture/database-isolation/lint/TypeScript checks, Nest build and both generated foundation tests passed. This is generated output, separate from the two hand-built references. MongoDB startup, private JWT configuration, explicit schema release and actual username/notes/media HTTP testing are the next runtime step; they were not performed during init. See [the username-auth contract](../docs/CLI-USERNAME-AUTH.md) for policy and evidence limits.
