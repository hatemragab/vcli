# PostgreSQL repository contract

This application contains one native `BaseRepository<T extends RepositoryEntity>` and PostgreSQL/Drizzle + pg only. `PostgresRepositorySchema<T>` supplies the feature owner's `PgTable`, explicit typed `PgColumn` map and allowed unique conflict targets. Account, installation, session and note services inherit it. There is no adapter, database union, runtime selection or application memory database. VCLI is unimplemented.

Conditions and order expressions are native Drizzle `SQL`, built inside trusted services with schema columns, `eq`, `and`, `desc`, or the `sql` tagged template. Values interpolate as parameters. Table/column identifiers come from static owner definitions. No controller accepts SQL, arbitrary filters, column names or repository options from HTTP clients. `sql.raw` is used only for the reviewed static identity migration; it must never receive input values.

## Methods and results

| Methods                                                                                     | Result and behavior                                                                                                                                                                                                                           |
| ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `create(entity, {context?})`, `createMany(entities, {context?})`                            | Full persisted plain records; native RETURNING order is unspecified. At most 1000 entities, SQL INSERT batches of 100, one atomic transaction across all batches. Empty input returns `[]`.                                                   |
| `findById(id, options?)`, `findOne(where, options?)`                                        | Selected record or `null`. ID reads use the native primary key predicate.                                                                                                                                                                     |
| `findByIdOrThrow`, `findOneOrThrow`                                                         | Same selected shape, or `RECORD_NOT_FOUND`.                                                                                                                                                                                                   |
| `findMany(where?, options?)`                                                                | Bounded selected records; default 100, maximum 1000.                                                                                                                                                                                          |
| `exists(where, {context?})`, `count(where?, {context?})`                                    | Boolean via SQL EXISTS, or exact safe-integer count.                                                                                                                                                                                          |
| `distinct(field, where?, {limit?, context?})`                                               | Typed field values, ascending with null last; default 100, maximum 1000.                                                                                                                                                                      |
| `findWithPagination(options?, where?)`                                                      | `{data,totalCount,totalPages,currentPage,hasNext,hasPrev}`. Page starts at 1, default size 20, maximum 100, maximum offset 1,000,000. Records and count share a transaction.                                                                  |
| `updateOne(where, changes, {context?})`, `updateMany(where, changes, {context?,allowAll?})` | `{affectedCount}` counts PostgreSQL matched/affected rows, including unchanged values; it is not a modified-only count.                                                                                                                       |
| `findByIdAndUpdate`, `findOneAndUpdate`                                                     | Selected record after the update or `null`. Changes cannot replace the ID; empty changes are rejected.                                                                                                                                        |
| `upsert(entity, {conflictTarget,set,updateWhere?,fields?,context?})`                        | Atomic native INSERT ON CONFLICT; selected inserted/updated record, or `null` if the conditional conflict update rejects. Target must exactly match an owner-declared non-partial unique constraint. `set` is explicit and cannot replace ID. |
| `deleteOne(where, {context?})`, `deleteMany(where?, {context?,allowAll?})`                  | `{affectedCount}`.                                                                                                                                                                                                                            |
| `findByIdAndDelete`, `findOneAndDelete`                                                     | Selected removed record or `null`.                                                                                                                                                                                                            |
| `iterate(where, {maxRows,batchSize?,fields?,context?})`                                     | Async selected records, ID ascending keyset traversal. Required maximum 1,000,000 rows; batches default 100, maximum 1000. Early exit buffers at most the current batch and leaves no cursor or owned transaction open.                       |

Read/returned-record options use `fields?: readonly K[]`, giving `Pick<T,K>` rather than pretending omitted fields exist. Omitting fields gives `T`. Writes bind each value with its owner-defined Drizzle column encoder; selected and returned records use that column's decoder. Native JSONB, timestamps/Dates, PostgreSQL arrays and bigints therefore retain their declared types, including bigint-as-number or bigint-as-bigint. Database-only metadata is excluded. Empty or unknown projections fail. Fields follow the owner contract; native `SQL<R>` output typing is the service author's responsibility and cannot validate SQL result types by itself.

Read and single-row mutation `orderBy` accepts native SQL expressions and always appends unique ID ascending for stable ties. One-row mutation selects and locks the first matching row in the same SQL statement and transaction. Read options `lock: 'update' | 'share'` require an explicitly supplied active transaction, so the lock remains useful to subsequent participant operations. An omitted context cannot produce a lock which expires before the caller can use it. `limit` applies to reads; returned-record single writes choose exactly one row.

Bulk update/delete without a condition, including `sql```, requires `allowAll: true`. Native SQL is trusted owner code: a deliberately tautological SQL condition cannot be proved safe by this helper, and owners must use the explicit opt-in for intended whole-table writes. There is no unrestricted HTTP bulk endpoint.

## Native SQL extensions and batches

Protected `db`, `columns`, `schema` and `database.context(context)` expose Drizzle and the current PostgreSQL transaction to the feature owner. Protected `queryRows<R>(sql<R>, {limit?,context?})` executes a typed SELECT for joins and grouping, with an outer transfer/buffering limit (default 100, maximum 1000). Expression results use native pg driver values; the service supplies any expression-specific decoding and an honest `SQL<R>` type. This is a native SQL SELECT contract; it does not parse an aggregation pipeline or perform population. `test/helpers/account-query-fixture.ts` demonstrates grouped counts and a self join using it. Larger specialized operations use the native database deliberately with their own bounds and transaction ownership.

Native batch capabilities are multi-value INSERT with all-or-nothing `createMany`, set-based conditional UPDATE/DELETE, and explicit conflict-target upsert. SQL constraints validate writes; there are no Mongoose document validators, save middleware, population, pipeline or bulkWrite APIs. Separate calls without a shared context commit separately, so a later failure can leave earlier committed work; share one context for a multi-call invariant. A caller catching an SQL error inside a transaction must understand that PostgreSQL aborts that transaction until rollback; this helper does not conceal failures with partial-success summaries.

## Transaction and iteration guarantees

An optional current opaque context is reused exactly; foreign or expired contexts fail. Otherwise a serializable transaction is started, with bounded serialization/deadlock/unique-race retries. Multi-record auth transitions retain account authority row locks, conditional credential versions, one-use proofs/refresh and shared participant context. An unknown commit acknowledgement remains `COMMIT_OUTCOME_UNKNOWN`; it is not safely retried as a new business operation. External mail, password hashing, provider I/O and realtime publication remain outside retryable callbacks.

Iteration opens and closes one bounded read transaction per batch when no context is supplied; concurrent writes can change what later batches observe. A caller needing a consistent snapshot consumes the complete iterator inside its current transaction callback. Iterator consumers must not perform external effects inside a retryable callback, since PostgreSQL may retry that callback. Pagination's count and rows share one serializable snapshot; this does not imply that separately requested pages share a snapshot.

`TEST_DATABASE_URL` enables real PostgreSQL regressions. Fixtures create a private generated schema, initialize all four schema owners, close their pools and drop only that schema. Database absence is an explicit skip; a supplied broken URL fails. They never start services or use application `DATABASE_URL` as a fallback. The JSONB/timestamp/array/bigint round-trip regression also covers returned writes, distinct and iteration.
