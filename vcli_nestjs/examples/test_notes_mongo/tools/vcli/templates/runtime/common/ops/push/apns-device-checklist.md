# Direct APNs and PushKit/CallKit

Configure `APNS_TEAM_ID`, `APNS_KEY_ID`, private regular `APNS_KEY_PATH` (.p8, <=16 KiB, no group/other access), base `APNS_TOPIC` bundle ID without `.voip`, and `APNS_PRODUCTION`. `PUSH_ENVIRONMENT` must match production/sandbox. Team/key IDs have ten uppercase alphanumeric characters. Register the correct application capabilities and provisioning entitlement; APNs tokens belong to an app/topic/environment. Do not paste credentials or raw tokens in shared logs.

Ordinary: APNs alert, priority 10, base topic; background: content-available=1, priority 5, base topic, no alert; VoIP: push-type=voip, priority 10, topic=base+'.voip', expiration=0, only a real current incoming call. Ordinary/background expiry comes from the bounded message TTL. Unregistered invalidation requires status 410 and a provider timestamp >= this registration's update time. BadDeviceToken/DeviceTokenNotForTopic cannot silently prune because environment/topic configuration may be wrong.

Enable Push Notifications and the background VoIP capability for the application target, link PushKit and CallKit, and retain a PKPushRegistry and CXProvider for application lifetime. The adjacent Swift example shows token update/invalidation and immediate CallKit reporting with completion. Supply `publish`/`revoke` closures that use the current authenticated installation; network failures require bounded application-owned retry while authority remains valid. CallKit UUID must be the application's authorized invitation UUID, not an arbitrary self-wakeup string. On SDKs requiring additional VoIP delegate methods, implement those current required methods too.

Implement TrustedCallInvitationPolicy at the composition edge using current application-owned call state. Permit only a ringing unexpired invitation addressed to this account and intended installation/generation/operation; deny completed, withdrawn, foreign or expired calls. Do not use a policy that returns true solely because callId is syntactically a UUID. Callers cannot pass policy through HTTP, and the self endpoint refuses VoIP. No generated calls product or automatic call authorization exists.

Use a real physical iPhone with correct provisioning, current token and network. Record invitation authorization, foreground/background/terminated receipt, immediate CallKit report and completion, accepted/declined/ended calls, expiry, sandbox/production isolation, registration refresh, logout/rebind fencing and delayed invalidation. Backend fakes and APNs receipt cannot satisfy these device checks.

Official contracts: https://developer.apple.com/documentation/usernotifications/sending-notification-requests-to-apns , https://developer.apple.com/documentation/usernotifications/handling-notification-responses-from-apns and https://developer.apple.com/documentation/pushkit/responding-to-voip-notifications-from-pushkit .
