# Selected release and isolated recovery

`npm run db:initialize` executes the finite generated release plan. Run it as a dedicated release operation with the selected configuration, before application startup. `src/generated/selected-release.ts` identifies its explicit owner versions and technical digests. Boot calls `assertSelectedReleaseReady` above core and before provider construction; it never runs a release. Custom schema migrations must be explicitly registered and versioned by the developer. There is no directory scanning, schema rollback, or cross-owner exactly-once claim.

The PostgreSQL outer session lock is 61921234, distinct from identity's 61921233. MongoDB uses a durable majority-written token/fence with no expiry or automatic takeover. Both retain manifests and component attempts in `vcli_release_history`. Completed owners survive a later failure. An interrupted callback or lost acknowledgement remains incomplete/unknown and blocks retry. Inspect native owner state privately, stop every old release runner and relevant writer, then supply a private decision file to `VCLI_RELEASE_DECISION` and run `npm run release:reconcile`. The file contains `quiesced:true`, exact `expectedHolder` (UUID or null), `expectedFence`, nonsecret `evidence` reference, and optional `attemptId` plus `decision:'completed'|'retry'`. A completion decision asserts inspected owner completion; retry explicitly accepts repeating possibly completed owner work. A stale decision fails. PostgreSQL also refuses recovery while a live session holds its lock; Mongo fencing cannot stop an old callback, so operator quiescence is required. Never infer quiescence from a timeout.

`npm run backup:create` reads the private JSON file named by `VCLI_BACKUP_PROFILE`; `npm run backup:restore` reads `VCLI_RESTORE_PROFILE`. Both use selected native tools already installed on the execution host: PostgreSQL `pg_dump`/`pg_restore` (matching server major or officially compatible), or Mongo Database Tools >=100.3 (`mongodump`/`mongorestore`, matching server/FCV compatibility). The tools run as argument vectors, with raw stdout/stderr suppressed. PostgreSQL passwords live only in temporary 0600 exclusive nofollow pgpass files; Mongo URIs live in similarly protected YAML config files. Connection strings never enter argv or public output. Native stderr is not retained because it may contain records or credentials. Use private operator diagnostics if a native operation fails. No binary is installed and no service/container is started by these commands.

Stop API writers, mail drains, cleanup jobs, realtime publication/ticket writes, upload/finalize/delete jobs, schema runners and external object writers for the entire snapshot. Quiesce native maintenance/balancing as appropriate. Native database snapshots alone cannot coordinate filesystem or remote objects. The supported profile is an explicit operator attestation and native dump plus exact private local media roots. Never copy .env, credential files or key rings into media roots. Root/child symlinks and special files fail. Native tools dump into private temporary files; database/media and the detailed inventory are individually authenticated with AES-256-GCM under an external 32-byte archive key. Directory permissions are 0700 and files 0600; keep key access and archive access separate. Work storage needs sufficient private disk space for raw transient dumps. Crash leftovers in the private work directory require identified operator cleanup; an incomplete archive has no final backup identity file.

The backup JSON fields are `schema:1`, `id`, `quiesced:true`, `quiescenceRef`, `databaseResourceId`, `archiveDirectory` (new destination), `workDirectory` (existing private directory), `encryptionKeyPath` (private raw 32-byte key), `encryptionKeyId`, `maximumBytes`, `maximumFiles`, `localRoots:[{id,path}]`, `externalSnapshots`, and `policy`. Source media is exactly `[{id:'media',path:LOCAL_STORAGE_ROOT}]` when storage is selected, including S3 staging; otherwise it is empty. Archive, work, key and media paths must be disjoint, with existing private parent directories. The policy contains `accessPolicyRef`, future ISO `retentionUntil`, `secretSourceRefs`, and `historicalMailKeyIds`. Required secret source names include `database.credentials`, selected `identity.signing-key-ring` or `identity.firebase-credential-source`, and `mail.delivery-key-ring` for reliable mail. No secret value is copied or hashed. Keep all historical mail key IDs needed by retained/restored payloads in the external key source, in addition to every currently configured key; archive encryption does not replace mail payload decryption keys. Preserve signing/provider credentials through the deployment's own secret-source contract.

For AWS/R2, `externalSnapshots` must contain the exact `aws:BUCKET` or `r2:BUCKET` resource, with `provider`, immutable `snapshotRef`, `immutable:true`, `accessPolicyRef`, `restoreContractRef`, and ISO `retentionUntil` at least the archive retention. These are explicit operator/provider contracts for exact immutable versions and their access/retention; **this command does not copy remote object bytes or verify provider snapshots**. The contract must preserve every database-referenced immutable object version and its namespace, plus staging consistency. Perform provider-native isolated copying/rebinding under that contract before application access; do not point an isolated test at a writable production bucket. Missing remote coverage refuses the backup. There is no automatic retention deletion, scheduler or ACL provisioning: the referenced operator policies own those actions and must remain effective.

The restore JSON contains `schema:1`, `isolated:true`, `targetEnvironment:'isolated'`, `quiesced:true`, `quiescenceRef`, `archiveDirectory`, `workDirectory`, `encryptionKeyPath`, `encryptionKeyId`, `targetDatabaseUrl` (private), `targetDatabaseResourceId`, `protectedDatabaseNames`, `localRoots:[{id,path}]` with new isolated destinations, `maximumBytes`, `maximumFiles`, `availableSecretSourceRefs`, `availableHistoricalMailKeyIds`, and `externalSnapshotAccessRefs`. A different resource label alone is insufficient: the database name must match `vcli_restore_[a-z0-9_]{1,48}`, differ from the source and every protected name, and the native target must be empty. The operator must also use an actually isolated account/network/resource; a label cannot establish provider isolation. Restore reserves a persistent native guard and refuses retry into a partial target. Media destinations must be absent and disjoint from all original roots and each other. No source database, volume, credentials or archive content is reset. PostgreSQL restores into the explicit target with one transaction, no --create/--clean and no source ownership/ACL grants; establish least-privilege target grants separately. Mongo uses namespace remapping, not --db archive semantics or --drop; a failed restore may leave partial target state. Keep the target isolated and inspect it; create a fresh target for another attempt.

Restore authenticates all payloads before native database execution and validates the restored release history. The result is deliberately `restored-unverified`: independently assert known rows, exact private media bytes, historical mail-key decryption, selected runtime behavior, secret-source accessibility and external immutable-object access in the isolated environment. A backup exit code is not restore proof, and a native restore exit is not provider/application acceptance. Do not advertise this profile as restore-tested until that evidence is recorded for the specific native tool/server versions. Image rollback neither reverses migrations nor restores deleted data. Preserve ordinary stop/redeploy volumes and credentials.

Official semantics: [pg_dump](https://www.postgresql.org/docs/16/app-pgdump.html), [pg_restore](https://www.postgresql.org/docs/16/app-pgrestore.html), [pgpass](https://www.postgresql.org/docs/16/libpq-pgpass.html), [mongodump config](https://www.mongodb.com/docs/database-tools/mongodump/#--config), [mongorestore namespace mapping](https://www.mongodb.com/docs/database-tools/mongorestore/#--nsFrom).
