# Private storage setup

This runbook does not provision resources or certify a provider. Use only the selected profile. Production buckets, credentials, CORS changes and lifecycle rules require the owner's deployment authorization.

Use a dedicated private durable directory owned by the application UID with mode `0700`. Linux pins no-follow directory descriptors through `/proc/self/fd`. macOS verifies the directory path and its ancestors, including ownership and write permissions, before opening files with no-follow flags. Put macOS development storage under a path owned by your user or root and keep its ancestors free of symlinks and access grants to untrusted users. Keep the root out of static serving and public web volumes, restrict access to trusted OS users, and leave the directory in place while the app runs. The owner and root can access it. Declare a single-instance or verified shared-volume topology. Independent per-container disks cannot share private media.

**Local objects.** VCLI creates a private development root at `storage/`. Owned media is written to `storage/<userId>/objects/`, with temporary uploads in the same owner's `incoming/` directory. Finalization uses an exclusive hard link in the same filesystem. Back up ready objects together with their owner database and retain the recorded storage profile.

**S3 spool.** Spool data remains immutable until the owner commits the ready state. Reconciled cleanup removes stale private spools. Retain the recorded storage profile.

**AWS S3.** Use a private general-purpose bucket with public access blocked and bucket-owner-enforced object ownership. Directory buckets and object-lock retention are unsupported. Grant the application role GetObject, PutObject and DeleteObject on `media/*`. If you enable versioning, also grant GetObjectVersion and DeleteObjectVersion. Keep the role's raw credentials private. Apply bucket policy and IAM controls to prevent other principals from overwriting ready keys or bypassing create-only writes.

**Cloudflare R2.** Use the named HTTPS account endpoint and `auto` region. The private bucket and token must allow the backend to read, write and delete `media/*` objects. Scope the token where platform permissions permit it. This profile uses R2's atomic conditional PutObject and Content-MD5. Application code verifies the SHA256 of the complete returned object.

**Provider staging.** Grant object read, write and delete access on `staging/*`. Configure bounded lifecycle expiry for that prefix as a final orphan backstop, longer than the app's maximum 900-second grant plus operation grace. Keep the staging rule away from `media/*`. Where versioning is enabled, configure noncurrent staging-version cleanup. Deleting a key alone can leave historical versions.

**Multipart.** Allow multipart creation, upload, completion and AbortMultipartUpload on `staging/*`, and ListBucketMultipartUploads on the bucket. Configure lifecycle cleanup for abandoned multipart uploads. Parts pass through the authenticated backend. Standard 8 MiB parts have uniform lengths except the final part. Completion sends If-None-Match, then the service promotes ready bytes separately.

**AWS direct POST.** Use a never-versioned bucket. The backend calls GetBucketVersioning before each grant and rejects both Enabled and Suspended. Grant `s3:GetBucketVersioning` and keep versioning disabled for the life of outstanding grants. POST policies bound each request. Replays can increase request count and concurrent ingress. Each grant specifies the exact private staging key, byte range, checksum and safe download metadata. Its scope is staging writes only, with no public ACL or read access. Adapt `aws-cors.example.json` to the exact authorized browser origin. Send signed fields unchanged, put the file last, and let the browser set the multipart Content-Type. Keep the app Authorization and X-Session-Token headers on app requests. An issued POST grant can write its staging key until expiry, including after logout. Ready bytes remain immutable. Verify the browser flow and actual provider behavior separately.

**S3 cleanup.** Provider timeouts remain unknown until readback or reconciliation. The API keeps a deleting tombstone and quota reservation during the operation grace and until cleanup succeeds with acknowledgement. Repeat cleanup with current owner authorization. Keep backend credentials and grants out of logs, diagnostics, support bundles and committed env files.

All downloads use the authenticated backend and immutable object references. Responses use Content-Type application/octet-stream, attachment, nosniff, private/no-store and sandbox CSP. Filename and MIME remain untrusted metadata. Separate-origin inline serving, scanning and public CDN are outside this profile. Logout prevents new mediated operations.
