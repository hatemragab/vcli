Build real, reviewable media/storage, mail and push capabilities for `examples/reference-api`, the hand-built expected NestJS output the owner wants to edit before CLI implementation. Do not implement VCLI, change other workers' files, claim generated provenance or complete CLI phases.

Read repository AGENTS.md, START-HERE, active shared docs, all phase README/TASKS/ACCEPTANCE (especially 05/06), the example AGENTS.md and docs/IMPLEMENTATION-CONTRACT.md. Obey its fixed config/security/mail contracts, factory paths, return shapes and ownership. Ask the coordinator for shared contract/dependency changes. The coordinator alone installs dependencies, owns root composition/config, runs builds/global formatting and starts services. No installs, commits, pushes, provisioning, paid services, deployments, emulators or unbounded runtime work.

Apply Hatem's SOLID, strict TypeScript, single quotes, kebab-case and one handwritten class/file rules. Pure domain/application code depends on small ports with explicit actor/time/IDs/facts and has no Nest/ORM/SDK/environment/network dependencies. SDKs and persistence belong in adapters; never leak database handles/generic filters into business contracts or import another owner's schema. Explicit Nest imports and factories compose dependencies; no @Global, forwardRef or service locator. Generate only active behavior, not empty modules/placeholders or artificial success. Public npm SDKs handle storage, SMTP, FCM, JWT signing/HTTP2 mechanics; verify current official docs via Context7/primary sources.

OWN ONLY: src/modules/media, mail, push; test/media*.test.ts and test/delivery*.test.ts; docs/storage.md and docs/delivery.md. Entry point createCapabilitiesRuntime(config, authority, mail) and createMailSender(config) must exactly match docs/IMPLEMENTATION-CONTRACT.md. The passed PrincipalAuthority establishes current authority; protected controllers import HttpSecurityModule.register(authority). Root creates mail sender first, passes it to identity and your factory. Capture action links stay in bounded private test-owned inspection handles and never enter ordinary HTTP debug routes/logs. Keep consumers provider neutral and error outcomes accepted/rejected/unavailable/unknown explicit.

MEDIA: implement HTTP begin upload, bounded streaming local transfer, finalize, authorized download and delete/cleanup. Real per-owner MongoDB/Mongoose and PostgreSQL/Drizzle+pg media/attempt persistence, plus explicit non-production memory profile. Record immutable provider/profile reference per finalized object so changing default doesn't reinterpret existing objects. Atomic quota/attempt reservations and guarded lifecycle changes; provider I/O outside retryable DB callbacks; reconcile uncertain completion. Local files live in private configured root, safe generated paths, symlink/traversal defense, exclusive writes, limits/timeouts/cancellation and immutable finalization. No public static upload directory. S3 uses the pinned AWS SDK with explicit AWS/R2/custom profile settings and presigned/multipart support only when its full integrity/immutability/size policy is implemented; refuse unsupported combinations clearly. Unique key alone does not establish final immutability. Include endpoint/region/addressing/signing/checksum/CORS behavior in setup docs, and do not assume all S3-compatible providers support every feature. Prefer a simple safe upload mode over pretending unsupported modes work. Conditional production validation must be honored.

MAIL: real capture and Nodemailer SMTP submission behind shared MailSubmitter, bounded capture/retention, safe escaped transport-neutral message rendering, typed delivery results and selected-provider production config. Capture is non-production and not proof of SMTP/inbox delivery. Identity's verification/reset flows use this exact sender. Explain Firebase-managed action mail versus app-delivered links without claiming SMTP equals Firebase auth. Use safe continuation URL policy where action links exist.

PUSH: authenticated installation-bound registration/update/removal, safe destination projections and generation fencing, explicit purpose routing to FCM ordinary and APNs VoIP/ordinary as configured, bounded retries/payloads and per-destination provider results. Use real Firebase Admin and Apple HTTP2/maintained crypto tooling at adapters. Recheck current account/session/binding eligibility; delayed cleanup for old tokens must not delete rotated destinations or route old-account work to a new owner. Do not expose unauthenticated arbitrary send endpoints or claim device display from provider acceptance. Missing configured provider actions must fail explicitly. Local auth can use FCM independently of Firebase identity.

DELIVER executable integrations, meaningful focused positive/negative/persistence/provider-translation tests, and documentation with endpoints, selected profiles, evidence limits and precise setup requirements. All requested families remain visible; unfinished advanced modes are named honestly. Do not describe mocks as real providers. Report actual checks run and blockers; partial implementation is not completed work. Use Orca worker_done; use ask/end-turn when shared decisions are required.
