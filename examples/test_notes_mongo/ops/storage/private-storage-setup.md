# Private storage setup

This runbook does not provision resources or certify a provider. Use only the selected profile. Production buckets, credentials, CORS changes and lifecycle rules require the owner's deployment authorization.

For local storage and every S3 profile's temporary spool, use a dedicated private durable directory owned by the application UID with mode0700. The Linux filesystem implementation pins no-follow directory descriptors through `/proc/self/fd`; Linux procfs must be available. Unsupported hosts fail explicitly. Do not expose this root with static serving, bind it to a public web volume, share it with untrusted OS users or rename it while the app runs. Owner/root access is not sandboxed. A local final object uses an exclusive hard link in the same filesystem. S3 spool data remains immutable until the owner commits ready; private stale spools are removed by reconciled cleanup. Back up local ready objects together with their owner database; retain the recorded storage profile. Declare single-instance or verified shared-volume topology; independent per-container disks do not provide shared private media.

All downloads use the authenticated backend and immutable version/ETag reference, Content-Type application/octet-stream, attachment, nosniff, private/no-store and sandbox CSP. Filename and MIME remain untrusted metadata. Separate-origin inline serving, scanning, public CDN and instant revocation of already issued storage grants are not implemented. Logout prevents new mediated operations; an existing AWS POST grant can write its staging key until its original expiry, without changing ready bytes.
