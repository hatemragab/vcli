# Private storage setup

This runbook does not provision resources or certify a provider. Use only the selected profile. Production buckets, credentials, CORS changes and lifecycle rules require the owner's deployment authorization.

For local storage and every S3 profile's temporary spool, use a dedicated private durable directory owned by the application UID with mode0700. The Linux filesystem implementation pins no-follow directory descriptors through `/proc/self/fd`; Linux procfs must be available. Unsupported hosts fail explicitly. Do not expose this root with static serving, bind it to a public web volume, share it with untrusted OS users or rename it while the app runs. Owner/root access is not sandboxed. A local final object uses an exclusive hard link in the same filesystem. S3 spool data remains immutable until the owner commits ready; private stale spools are removed by reconciled cleanup. Back up local ready objects together with their owner database; retain the recorded storage profile. Declare single-instance or verified shared-volume topology; independent per-container disks do not provide shared private media.

AWS S3: direct POST mode requires a never-versioned bucket: the backend calls GetBucketVersioning before each grant and rejects both Enabled and Suspended (s3:GetBucketVersioning permission is required). Keep bucket versioning disabled for the lifetime of outstanding grants; changing it is an operator policy change. Mediated/multipart modes can use versioned buckets. POST policies bound each request, not the number or concurrent ingress rate of replayed requests; choose mediated mode for backend concurrency control. Create a private general-purpose bucket, block public access and use bucket-owner-enforced object ownership. Do not use a directory bucket or object-lock retention with this profile. The application role needs GetObject/PutObject/DeleteObject on `media/*` and `staging/*`, AbortMultipartUpload on `staging/*` and ListBucketMultipartUploads on the bucket. With versioning it also needs GetObjectVersion/DeleteObjectVersion; retained noncurrent staging versions need a lifecycle policy. Do not distribute this role's raw credentials. Apply bucket policy/IAM controls so other principals cannot overwrite ready `media/*` keys or bypass create-only writes. A signed browser POST contains exact private staging key, exact byte range, checksum and safe download metadata; it grants no ready-key write, no public ACL and no read. AWS direct needs the public SDK POST helper; R2/local output must omit it. Adapt `aws-cors.example.json` to an exact authorized browser origin. Form fields are signed; send them unchanged, file last, without app Authorization or X-Session-Token headers to the bucket. Do not manually set multipart/form-data Content-Type. A CORS JSON file and an opaque fake ETag do not prove browser or provider behavior.

Cloudflare R2: use only the named HTTPS account endpoint and `auto` region; arbitrary custom S3 endpoints are rejected. A private bucket/token must allow the backend's object read/write/delete, multipart and bucket multipart-list operations. Use a separately scoped token where platform permission granularity permits it. No public bucket/dev URL or CDN is required. This profile uses R2's atomic conditional PutObject and Content-MD5; it does not send unsupported AWS SHA256 checksum or SSE headers and still verifies the complete returned object's SHA256 in application code. Direct POST mode is rejected. Parts pass through the authenticated backend, so browser-to-R2 CORS is unnecessary for this mode. Standard 8 MiB parts have uniform lengths except the final part. A condition sent only at initiation does not constrain completion; completion also sends If-None-Match and ready bytes are promoted separately.

For AWS/R2, configure bounded lifecycle expiry for **staging/** and abandoned multipart uploads as a final orphan backstop, with expiry longer than the app's maximum900-second grant plus operation grace. Never apply a short staging rule to **media/**. When versioning is enabled, configure noncurrent staging-version cleanup as well; deleting a key alone can leave historical versions. Provider timeouts are unknown until readback/reconciliation. The API keeps a deleting tombstone and quota reservation during the operation grace and until acknowledged cleanup succeeds; repeat cleanup with current owner authorization. Backend credentials and grants must never enter logs, diagnostics, support bundles or committed env files.

All downloads use the authenticated backend and immutable version/ETag reference, Content-Type application/octet-stream, attachment, nosniff, private/no-store and sandbox CSP. Filename and MIME remain untrusted metadata. Separate-origin inline serving, scanning, public CDN and instant revocation of already issued storage grants are not implemented. Logout prevents new mediated operations; an existing AWS POST grant can write its staging key until its original expiry, without changing ready bytes.
