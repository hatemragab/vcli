# Realtime reference

This is a hand-built expected-output example, not VCLI-generated output. Generator phases and provider/device/deployment acceptance remain separate. Choose exactly one `REALTIME_DRIVER`: `socketio` (default), `ws` or `centrifugo`. These are **single API instance** profiles; there is no Redis fanout, shared admission-ticket store, cluster support, durable replay, presence, exactly-once delivery or direct JWT-grant implementation.

`createOperationsRuntime(config, authority, events)`, exported from [realtime.module.ts](../src/modules/realtime/realtime.module.ts), returns `module`, `publisher`, `attach(httpServer)` and `close`. The supplied `events: DiagnosticEvents` is the shared application logger; realtime does not create, export or close the retained writer, reader or logger. Registration composes the selected protocol and registers the same instances as ordinary Nest providers. Import the returned Nest module explicitly, initialize Nest, then call `attach` before listening. Pass its shared `EventPublisher` to business operations at composition. The notes operation persists first and publishes `notes.created` with its explicit event ID and `{noteId}` payload. Publication is an advisory hint; the account audience comes from the authorized operation, never client room/channel/owner fields. No socket SDK type enters that business contract.

[RealtimeService](../src/modules/realtime/realtime.service.ts) owns the bounded connection registry, current-authority checks and advisory publication, and is exported directly for Nest consumers. `RealtimeTicketService` owns hashed one-use admission; `SocketIoService`, `NativeWsService`, `CentrifugoConnectionService` and `CentrifugoApiService` retain their distinct wire protocols and private provider mechanics in the same flat feature directory. Controllers inject the ticket/connection services directly. The composition root passes the shared logger through the small `DiagnosticEvents` contract. `RealtimeModule` neither imports nor re-exports `DiagnosticsModule`; logger/retained-reader registration and cleanup belong to the application composition. Realtime has no dependency on the diagnostics feature. Shared event facts live in `core`, which imports no feature. The old adapter names and standalone runtime-factory files have been removed.

The shared publisher reports `attempted`, `provider-accepted`, `audience-ineligible` or `unavailable` and the selected transport. Attempted/provider-accepted does not prove receipt. Socket.IO volatile sends may drop; native ws sends bound buffered bytes; Centrifugo returns provider acceptance only after its documented successful API envelope. No retries or durable outbox are implied. Events are validated/bounded before transport. Recipient application data must always be fetched through authorized REST.

## Identity and bounds

All profiles use the same `PrincipalAuthority.verify(AccessProof)` or `current(verifiedSessionId)` provided by the identity owner. A bare session ID cannot authenticate an external client. A verified principal's account/session/installation and original credential expiry fence subsequent use; `current` must keep enforcing durable revocation and installation binding. An API bearer refresh does not silently extend an already admitted connection: reconnect with new proof/ticket. Firebase uses the ID token plus opaque `X-Session-Token`; local uses an access JWT.

Limits are deliberately modest review defaults: 128 connections per API, eight per session, 32 pending admissions, 60 incoming application messages/minute, one in-flight client message per connection, 3-second initial admission timeout, 2-second authority-call deadline, eight concurrent publications, configured payload size (default 16 KiB), 64 KiB native-ws queued bytes, and no application send queue. Tickets are 256-bit random values retained only as hashes, at most 512 overall/four outstanding per session and ten issued per session per minute, single-use and purpose-bound, with TTL at most 30 seconds and no later than original credential expiry. Ticket consumption deletes synchronously before any awaited current-authority check; a failure burns the ticket. This atomicity is local-process only.

Connections are rechecked every second while idle and immediately before private publication/accepted ping. A failed/unavailable check closes the binding; an idle check has a nominal one-second scheduling plus two-second authority deadline bound, subject to event-loop/host availability. Publication rechecks run concurrently across the bounded registry and recheck identity before dispatch. No network can recall bytes dispatched just before revocation; clients must perform an authorized REST read after a hint. Old disconnects remove their exact connection only. Realtime shutdown stops admission and closes its registry/connections/timers. The application composition closes HTTP and providers, records terminal application events, and then flushes/closes retained diagnostics within its separate deadline. Socket.IO's close also closes its attached HTTP server; root shutdown owns that shared server lifecycle.

## Socket.IO

The default uses Socket.IO 4.x, explicitly WebSocket-only at `REALTIME_PATH=/realtime`; it requires no polling stickiness or Redis. It does not advertise polling or multiple replicas. `allowRequest` enforces exact configured Origin and bounded Engine.IO counts. Credentials go only in the bounded handshake `auth` object:

```js
// Local
const localProof = { kind: 'local', accessToken };
// Firebase
const firebaseProof = { kind: 'firebase', idToken, sessionSecret };
```

URL credential/query fields are refused and handshake credentials are cleared after verification. Only `ping(null, ack)` is accepted; it returns `{version:1,type:'pong'}` after current-authority checking. Unsupported commands/subscriptions disconnect. Private notifications arrive as `notification` with the shared `{id,type,payload}` event; no client-selected rooms are exposed. `admitted` carries `{version:1,recovery:'REST'}`. Use [the actual client](../clients/socket-io.mjs) with the pinned `socket.io-client` dependency, a proof supplier, a REST recovery callback and a safe denied-state callback.

## Browser native ws

An authenticated `POST /api/realtime/tickets` has no owner/session body; `PrincipalGuard` supplies the principal. It returns `{ticket,expiresAt}`. Open the configured ws/wss endpoint with no query credentials. Browser Origin is checked. The first text frame, at most 512 bytes, must be:

```json
{ "version": 1, "type": "authenticate", "ticket": "<fresh one-use ticket>" }
```

Before admission, no private event, command or subscription is available. Successful admission returns `{version:1,type:'admitted',recovery:'REST'}`. Notifications use `{version:1,type:'notification',event:{id,type,payload}}`. A post-admission `{version:1,type:'ping',requestId:<uuid>}` returns a correlated pong after authorization. Invalid/binary/rate-excess frames close with policy denial; concurrent frames or slow buffers terminate. Protocol ping/pong checks liveness every 15 seconds and terminates a connection on its next unanswered check (up to approximately 30 seconds). Reconnect obtains a fresh HTTP ticket; replay, expired tickets and revoked sessions are denied. [The browser client](../clients/native-ws.mjs) demonstrates this exact flow and exposes closure so its caller can choose bounded reconnect/backoff or reauthentication.

## Centrifugo service

Use the separately configured [Centrifugo v6.10.3 service](../ops/centrifugo/config.json). No service was started by this worker. The service is a memory-engine single-node profile; application session authority remains in the selected application database. Set `CENTRIFUGO_API_URL` to the **private internal API prefix**, for local Compose `http://127.0.0.1:59000/api`; `CENTRIFUGO_API_KEY` and `CENTRIFUGO_PROXY_SECRET` must be different private values, the latter at least 32 characters. Public clients connect only to `ws://127.0.0.1:58000/connection/websocket` in local development, WSS behind reviewed ingress in deployment.

The protected `POST /api/realtime/centrifugo-grants` returns a one-use ticket. The maintained `centrifuge@5.8.0` client passes `{ticket}` as connection `data` through `getData`, which obtains a fresh grant on reconnect. [The client adapter](../clients/centrifugo.mjs) accepts the SDK's real `Centrifuge` constructor; a consuming frontend installs that exact client separately. It listens to server-side `publication` and never chooses private channels. API credentials and callback secrets never reach that client.

Centrifugo POSTs documented connect/refresh proxy envelopes to `/api/realtime/centrifugo/connect` and `/refresh`. Supply the dedicated callback secret using Centrifugo's `client.proxy.{connect,refresh}.http.static_headers`; the local Compose variable `CENTRIFUGO_CALLBACK_HEADERS` is a private JSON object `{"X-Centrifugo-Proxy-Secret":"<private value>"}` matching the API's proxy secret. **Both `http_headers` and `emulated_headers` remain empty**: client values must never override that authoritative header. Put callbacks and internal API on private/restricted networks, block callbacks at public API ingress, and validate Origins separately. When the API runs natively, the Compose callback host gateway requires `HOST=0.0.0.0` plus host firewall restrictions; when containerized, change the callback URL to its actual private service address. A loopback-bound API cannot receive a bridge-container callback.

The connect proxy atomically consumes the grant, rechecks authority and assigns a fresh `private:<hash-of-provider-client-id>` channel for that exact connection. Cached client channel hints are ignored. Per-connection channels prevent a revoked connection from receiving a sibling's future account publication even if an outbound disconnect fails. Success uses `result:{user,expire_at,subs}`; permanent rejection uses `disconnect:{code:4501,reason:'unauthorized'}`; temporary connect-authority failure uses `error:{code:100,message:'internal server error'}`. Refresh is the refresh-specific `result:{expired:true}` denial or `result:{expire_at}` success. Only connect/refresh proxies are installed; subscriptions, client publish and RPC are not enabled, so no fabricated subscribe-proxy route exists.

Backend publication POSTs `/api/publish`, authenticates `X-API-Key`, requires a successful bounded response envelope and reports unknown/failure as unavailable without blind retry. Revocation invokes private `/api/disconnect` with both user and exact client. There are at most 16 concurrent private API calls, a two-second request timeout, redirects denied and 4 KiB reply limit. Service queues are bounded to 64 KiB/client. Server connection expiry is renewed through current-authority refresh approximately every five seconds; callback failures expire rather than extend authority. The API removes provider references not refreshed for 15 seconds because Centrifugo has no disconnect webhook; rapid reconnects can temporarily exhaust the eight-per-session limit. External service expiry/grace, outages, header precedence and routing still require real SDK/service evidence. The immediate pre-publication current check plus separate private connection channel enforce the backend disclosure policy even while service-disconnect confirmation is unavailable.

## REST recovery and evidence

After every admission/reconnect, on gaps/outage/drop and after receiving a hint, call authenticated `GET /api/notes` (and read a known note through its REST contract). Deduplicate hints by event ID only as a client convenience; it does not restore missed events. The notes list is bounded; paginate according to the owner contract when that capability is added. There is no event-history cursor, global event sequence, durable resume or exactly-once claim here. REST authorization remains required even if a hint was previously authorized.
