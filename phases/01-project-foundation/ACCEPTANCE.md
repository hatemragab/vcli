# Phase 01 acceptance

**Status: implemented locally for the private Linux bootstrap profile.** See [per-ID evidence](../../docs/CLI-VERIFICATION.md#phase-acceptance-mapping). Follow the [design](README.md), [tasks](TASKS.md), and shared [evidence rules](../../docs/VERIFICATION.md).

## Setup and evidence

Use isolated temporary destinations and Phase 00's pinned toolchain. No database, cloud credentials, containers, or provider calls are needed. Record CLI/blueprint revision, host/tool versions, exact command, exit status, sanitized output, resulting file list, and asserted HTTP responses when relevant. Treat static, boot, and request evidence separately.

| ID          | Scenario and setup                                                                                                                        | Expected result and retained evidence                                                                                                                                                                                                      |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **P01-A01** | Initialize a new project with installation skipped; repeat with `init .` in a separate empty directory.                                   | Both create the documented readable layout and desired/realized metadata. Installation/check state remains pending. Retain file manifests, parsed config, and command results.                                                             |
| **P01-A02** | Place a sentinel file in the destination, propose an escaping path, and provide a destination symlink outside the permitted root.         | Each is rejected before writing outside the allowed plan; sentinel bytes and external tree are unchanged. | **P01-A04** | Inspect a source-only project and run basic doctor with invalid toolchain/configuration fixtures.                                         | State remains truthful; unsupported versions/config names are reported without installing tools or contacting providers. ## Exit gate

All six scenarios need an identified result and evidence. Required failures or missing build/boot evidence keep the phase incomplete; an environmental blocker is recorded rather than converted to a pass. Confirm a named release/patch owner and readable ownership documentation before handing off to [Phase 02](../02-safe-generation/README.md). Update the [status board](../STATUS.md) only from reviewed results.
